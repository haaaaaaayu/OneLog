# 한끼로그 (OneLog)

**남아서 버리는 식재료를, 다음 한 끼로.**

첫 자취생이 한 번 산 식재료를 버리지 않고 끝까지 쓰도록, 레시피 선택부터 식단 계획·장보기·조리·남은 재료 활용까지를 하나로 잇는 AI 식사 플래너입니다.

멋쟁이사자처럼 14기 프로젝트.

## 왜 만들었나

문제는 레시피가 부족한 게 아닙니다. **한 끼에 필요한 양과 마트가 파는 단위가 다릅니다.**

대파 한 단을 사면 요리에는 반 대만 쓰고 나머지는 냉장고에서 시듭니다. 남은 재료를 다음에 언제 어떻게 쓸지 계획이 없으니 식비와 식재료가 같이 버려집니다.

한끼로그는 필요량과 구매량을 분리해서 계산하고, 남을 양을 미리 알려주고, 그 남는 재료로 다음 끼니를 제안합니다.

## 핵심 원칙

- **수량·단위·가격·예산·재고 차감은 전부 결정론적 코드로 계산합니다.** 생성형 AI의 추측을 계산 결과로 쓰지 않습니다.
- **근거 없는 값을 만들지 않습니다.** 판매 단위가 확인되지 않은 재료는 구매량을 계산하지 않고 사용자 확인을 요청하며, 예산도 `확정`으로 표시하지 않습니다.
- **근거 없는 단위 환산을 하지 않습니다.** 재료마다 명시된 단위끼리만 바꿉니다.
- **AI가 식단을 일방적으로 확정하지 않습니다.** 먹고 싶은 메뉴는 사용자가 고르고, 계산과 계획을 앱이 맡습니다.

## 구성

```
app/, lib/, tests/     웹 프로토타입 (Next.js 15 · React 19 · TypeScript · Vitest)
ios/OneLog/            iOS 네이티브 앱 (SwiftUI · Xcode 26)
ios/tools/             식약처 레시피·판매 단위 빌드 타임 임포터 (Python)
AGENTS.md              기획 해석 순서, 기능 우선순위, 구현 현황
```

웹은 초기 프로토타입으로 퍼널 검증까지 하고 그대로 두었습니다. 현재 개발은 iOS 네이티브에서 진행합니다.

## 데이터

- 레시피: 식품안전나라 `COOKRCP01` 1,156건을 빌드 타임에 변환해 950건 + 큐레이션 6건. 앱은 외부 API를 호출하지 않고 번들 JSON만 읽습니다. (공공누리 출처 표시는 마이페이지)
- 대표 판매 단위: 마트 소포장 기준 185종. 여기 없는 재료는 구매량을 계산하지 않습니다.
- 현재 956건 중 **124건**이 구매량까지 완전히 계산됩니다.

## 실행

```bash
# 웹
npm install && npm run dev
npm test

# iOS
open ios/OneLog/OneLog.xcodeproj
xcodebuild test -project ios/OneLog/OneLog.xcodeproj -scheme OneLog \
  -destination 'platform=iOS Simulator,name=iPhone 16e'
```

### 동네 나눔(F26·F27)을 쓰려면

Firebase 설정이 필요합니다. 없어도 나머지 기능은 그대로 동작하고, 나눔 화면만 미연결 안내를 띄웁니다.

1. Firebase 콘솔에서 iOS 앱 등록 (번들 ID `com.onelog.native`)
2. `GoogleService-Info.plist`를 `ios/OneLog/OneLogApp/`에 넣고 Xcode 타깃 리소스로 추가
3. Authentication에서 익명 로그인 활성화
4. `firebase deploy --only firestore:rules`

식약처 레시피를 다시 굽는다면 `ios/tools/.api_key`에 인증키를 넣습니다. 이 파일은 커밋하지 않습니다.

## 현재 상태

P0 기본 흐름과 F13·F14·F20~F24는 부분 구현, F26 공동구매·소분과 F27 채팅은 화면과 도메인까지 구현하고 서버 연결 검증이 남았습니다. 기능별 상태와 남은 작업은 [AGENTS.md](AGENTS.md)의 `현재 구현 현황`에 정리되어 있습니다.

`완료` 표시는 요구사항·테스트·실제 화면 흐름 확인이 모두 끝난 경우에만 씁니다.
