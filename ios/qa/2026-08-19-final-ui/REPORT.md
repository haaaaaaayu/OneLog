## 캡처한 사용자 흐름

1. 온보딩: 시작 → 로그인 → 로그인 오류 → 기본 정보(미인증) → 동네 검색 → 지도 확인 → 기본 정보(인증) → 조리도구 → 불호 → 알레르기.
2. 홈·레시피: 빈 식단 홈 → 레시피 탐색 → 검색 결과 → 검색 빈 상태 → 찜 → 레시피 상세.
3. 마이페이지: 메인 → 요리 숙련도 시트 → 불호·알레르기 시트 → 내 정보 수정 → 설정 → 알림 설정.
4. 식단 만들기: 기간 → 끼니 → 예산 → 분석 → 3개 식단안 → 식단 확인 → 최종 확인 → 전체 재료 → 보유 재료 → 가격·판매 단위 → 업그레이드.
5. 식단 실행: 식단관리 → 장보기 → 식단이 있는 홈 → 레시피 탐색.
6. 재료소분: 진입 → 재료 선택 → 진행 중 나눔 → 알림함 → 받은 요청 → 채팅 → 약속.

승인한 원본 PNG는 `accepted/` 아래의 `all`, `plan`, `share` 폴더에 있다. 전체 흐름 축소판은 `accepted-all.png`, `accepted-plan.png`, `accepted-share.png`다.

## Figma 대조 결과

- 온보딩 시작, 홈, 레시피 탐색, 식단 만들기 1단계, 재료소분 선택, 마이페이지를 같은 393×852 상태로 Figma 원본과 나란히 대조했다.
- 색상, Noto Sans KR 굵기, 카드 반경, 상하단 안전영역, 고정 CTA와 4개 하단 탭의 구조가 기준과 일치한다.
- 홈의 날짜·식단, 레시피 개수, 나눔 재료·이웃은 실행 시점 데이터이므로 Figma 샘플 값과 다르지만 동일한 컴포넌트 구조와 상태 규칙을 유지한다.
- 검색 결과·검색 빈 상태는 입력 중 키보드가 열린 실제 상태도 별도로 확인했다. 키보드가 하단 탭 위에 올라오며 검색 필드와 결과/빈 상태 마스코트를 침범하지 않는다.

## 이번 QA에서 수정한 결함

1. 재료소분 채팅의 메시지 시각과 약속 날짜가 시뮬레이터 로캘에 따라 영어로 보이던 문제를 `ko_KR` 포맷으로 고쳤다.
2. 마이페이지 `불호 음식·알레르기` 시트 캡처가 오래된 접근성 식별자를 사용해 빠지던 테스트 하네스를 현재 식별자로 고쳤다.

## 강점

- 식단 만들기 1~11 흐름의 고정 하단 버튼과 스크롤 본문이 겹치지 않는다.
- 오류·빈 상태·미인증·가격 미확정 같은 비정상 상태가 정상 상태와 같은 디자인 언어로 제공된다.
- 불호와 알레르기가 시각적으로 분리되고, 가격 미확정은 확정 금액처럼 보이지 않는다.
- 받은 요청 → 채팅 → 약속 흐름에서 상태와 주요 행동이 한 화면에 명확히 드러난다.

## 남은 위험과 제한

- 중간: `figmaText`는 픽셀 기준 고정 포인트 폰트를 사용해 Dynamic Type 확대를 따르지 않는다. 이번 합격은 기본 글자 크기의 393×852 기준이며, 접근성 큰 글자 전용 레이아웃은 별도 설계·검증이 필요하다.
- 낮음: 레시피 원격 이미지가 아직 내려오지 않은 순간에는 Figma의 회색 사진 플레이스홀더가 먼저 보인다. 로딩 실패 시에도 레이아웃은 유지된다.
- 실기기 전용: Google OAuth 콜백, GPS 권한·실좌표, Firebase 실시간 나눔/채팅/약속, 실제 OpenAI 응답은 시뮬레이터 QA 범위 밖이다.
- 시각 QA는 기준 글자 크기·라이트 모드로 수행했다. 다크 모드와 VoiceOver 읽기 순서는 별도 접근성 라운드가 필요하다.
